5. HOW IT WORKS - COMPLETE FLOW
================================================================================

SCENARIO: User on Salesforce page clicks chat widget

Step 1: Page Load
├─ Salesforce page loads
├─ Lightning Web Component (LWC) initializes
├─ LWC detects it's not already loaded
├─ LWC creates <script> element pointing to chat-widget.js
└─ Script injected into document.body

Step 2: Chat Widget Script Loads (chat-widget.js)
├─ IIFE (Immediately Invoked Function Expression) executes
├─ Checks if widget already exists (prevents duplicates)
├─ Creates chat button element
│  ├─ Position: fixed (bottom: 20px, right: 20px)
│  ├─ Styling: Blue button with hover effects
│  └─ Icon: 💬 emoji
├─ Creates chat window element (initially hidden)
│  ├─ Position: fixed (above button)
│  ├─ Dimensions: 350px width × 500px height
│  ├─ Contains: Header, Messages container, Input field
│  └─ Style: White background with shadow
├─ Appends both elements to document.body
└─ Attaches click handlers

Step 3: User Interaction - Open Chat
├─ User clicks chat button
├─ Click handler executes: chatWindow.style.display = 'flex'
├─ Chat window becomes visible with animation
├─ Welcome message displayed: "👋 Hello! How can I help you find a product?"
└─ Input field ready for user to type

Step 4: User Sends Message
├─ User types: "Looking for laptops"
├─ User clicks Send button
├─ Message validation: Check if input.value.trim() is not empty
├─ If valid:
│  ├─ Create user message element
│  ├─ Style it: Right-aligned, blue background
│  ├─ Add to messagesContainer
│  ├─ Clear input field
│  ├─ Scroll to bottom
│  └─ Send to backend API
└─ If empty: Do nothing

Step 5: Backend Processing (/api/chat)
├─ POST request received at /api/chat
├─ Body contains: { message: "Looking for laptops" }
├─ Endpoint logic:
│  ├─ Extract message from request body
│  ├─ Convert to lowercase for processing
│  ├─ Check for keywords (laptop, mouse, cable, etc.)
│  ├─ Generate response based on keywords
│  ├─ Query mock database for matching products
│  └─ Return: { reply: "message", products: [] }
├─ Response sent back to frontend
└─ HTTP 200 OK with JSON response

Step 6: Frontend Displays Response
├─ Response received from API
├─ Parse JSON response
├─ Create bot message element
├─ Style it: Left-aligned, gray background
├─ Add to messagesContainer
├─ Auto-scroll to latest message
└─ Wait for next user input

Step 7: Close Chat
├─ User clicks close button (✕) in header
├─ Click handler executes: chatWindow.style.display = 'none'
├─ Chat window hidden
├─ Chat button still visible
└─ User can reopen by clicking button again

6. COMPONENT BREAKDOWN
================================================================================

6.1 CHATWIDGET.TSX (Main Component)
────────────────────────────────────
Purpose: Orchestrate the chat widget state and behavior
Type: Client Component ('use client')
Imports:
- React hooks (useState)
- useChat custom hook
- ChatButton, ChatWindow components

Key State:
- isOpen: boolean (chat window visible/hidden)

Key Functions:
- toggleChat(): Toggle chat window open/closed
- clearMessages(): Clear chat history when opening

Responsibilities:
- Render chat button
- Render chat window (conditional)
- Manage chat visibility state
- Pass props to child components

Props: None (root component)

Returns JSX:
- Conditional rendering of ChatWindow
- Always render ChatButton

6.2 CHATBUTTON.TSX (Button Component)
─────────────────────────────────────
Purpose: Render floating chat button
Type: Client Component
Props:
- onClick: () => void (from parent)

Key Features:
- Fixed position (bottom: 20px, right: 20px)
- Circular shape (border-radius: 50%)
- Blue background (#0070f3)
- Emoji icon (💬)
- Hover effects (scale 1.1)

Styling: Inline styles (cssText)
Interaction: Click to toggle chat window

6.3 CHATWINDOW.TSX (Chat Display)
──────────────────────────────────
Purpose: Display chat messages and input
Type: Client Component
Props:
- messages: ChatMessage[] (array of messages)
- input: string (current input value)
- loading: boolean (show typing indicator)
- onInputChange: (e: React.ChangeEvent<HTMLInputElement>) => void
- onSubmit: (e: React.FormEvent) => void
- onClose: () => void (close button handler)

Key Features:
- Auto-scroll to latest message
- Message distinction (user vs bot)
- Typing indicator
- Empty state message

Styling:
- Fixed position
- White background
- Blue header
- Shadow effects

Layout:
- Header (title + close button)
- Messages container (scrollable)
- Input container (input + send button)

6.4 PRODUCTSEARCH.TSX (Search Component)
─────────────────────────────────────────
Purpose: Search for products in real-time
Type: Client Component
Props:
- onProductSelect?: (product: Product) => void

Key Features:
- Real-time search as user types
- API call to /api/products
- Product card display
- Image, name, price display

API Call:
GET /api/products?search={query}

Response:
{ products: Product[] }

Loading State: Shows "Loading..." text

Error Handling: Gracefully catches errors, shows empty results

7. API ENDPOINTS
================================================================================

7.1 POST /api/chat
──────────────────
Purpose: Process chat messages and return responses
Method: POST
Host: https://nextjs-chat-widget-xi.vercel.app
Path: /api/chat

Request Format:
{
  "message": "Looking for laptops"
}

Request Headers:
Content-Type: application/json

Response Format (200 OK):
{
  "reply": "I found some great laptops for you!",
  "products": [
    {
      "id": "1",
      "name": "Laptop Pro",
      "description": "High-performance laptop",
      "price": 1299,
      "imageUrl": "/placeholder.png",
      "category": "Electronics"
    }
  ]
}

Error Response (500):
{
  "reply": "Sorry, I encountered an error. Please try again."
}

Processing Logic:
1. Extract message from request body
2. Convert to lowercase
3. Check for keywords:
   - "laptop" → Show laptops
   - "mouse" → Show accessories
   - "cable" → Show cables
4. Return matching products
5. Generate contextual response

7.2 GET /api/products
─────────────────────
Purpose: Search for products by query
Method: GET
Host: https://nextjs-chat-widget-xi.vercel.app
Path: /api/products

Query Parameters:
- search: string (product search query)

Example: GET /api/products?search=laptop

Request Headers:
Accept: application/json

Response Format (200 OK):
{
  "products": [
    {
      "id": "1",
      "name": "Laptop Pro",
      "description": "High-performance laptop",
      "price": 1299,
      "imageUrl": "/placeholder.png",
      "category": "Electronics"
    }
  ]
}

Empty Result:
{
  "products": []
}

Search Logic:
1. Get search parameter
2. Convert to lowercase
3. Filter products by:
   - Product name contains search
   - Product description contains search
   - Product category contains search
4. Return matching products

Performance:
- In-memory database (mock data)
- Instant response (<100ms)
- No database queries needed

9.1 LIGHTNING WEB COMPONENT SETUP
──────────────────────────────────

Step 1: Create LWC in your Salesforce Dev Org
Location: Setup → Lightning Web Components → New

Three Files to Create:

FILE 1: chatWidgetEmbed.js
────────────────────────────
import { LightningElement, api } from 'lwc';

export default class ChatWidgetEmbed extends LightningElement {
    @api widgetTitle = 'Product Search Chat';
    @api primaryColor = '#0070f3';
    @api widgetUrl = 'https://nextjs-chat-widget-xi.vercel.app';
    @api apiKey;

    connectedCallback() {
        this.loadChatWidgetScript();
    }

    loadChatWidgetScript() {
        if (document.getElementById('nextjs-chat-widget-script')) return;

        const script = document.createElement('script');
        script.id = 'nextjs-chat-widget-script';
        script.src = `${this.widgetUrl}/chat-widget.js`;
        script.async = true;
        
        script.onload = () => {
            console.log('✓ Chat widget loaded');
            window.chatWidgetConfig = {
                title: this.widgetTitle,
                primaryColor: this.primaryColor,
                apiKey: this.apiKey
            };
        };

        document.body.appendChild(script);
    }
}

9.2 TROUBLESHOOTING SALESFORCE INTEGRATION
───────────────────────────────────────────

Issue: "Failed to load widget" error
Solution: 
- Check CSP Trusted Sites configuration
- Verify URL is correct in LWC
- Clear Salesforce cache (Setup → System Overview → Clear Cache)
- Check browser console for detailed errors

Issue: Chat button appears but doesn't open
Solution:
- Check if script loaded successfully
- Verify browser allows cross-domain JavaScript
- Check for CSS conflicts with Salesforce styles

Issue: CORS errors in console
Solution:
- Add domain to CSP Trusted Sites
- Verify next.config.js has proper CORS headers
- Test with incognito window (bypasses cache)

Issue: Chat window appears off-screen
Solution:
- Check z-index values (should be 999999)
- Verify position: fixed CSS is applied
- Test on different screen resolutions

public class ProductController {
    @AuraEnabled(cacheable=true)
    public static List<Product__c> getProducts(String searchTerm) {
        return [SELECT Id, Name, Description__c, Price__c FROM Product__c 
                WHERE Name LIKE :('%' + searchTerm + '%')];
    }
}

12. TROUBLESHOOTING
================================================================================

12.1 COMMON ISSUES & SOLUTIONS
──────────────────────────────

Issue: "Cannot find module '@/components/ChatWidget'"
Solution:
- Check tsconfig.json has: "baseUrl": "src" and path aliases
- Restart TypeScript server (Ctrl+Shift+P → Restart TS)
- Verify file exists at src/components/ChatWidget.tsx

Issue: Chat button not appearing
Solution:
- Check script loaded without errors (Console tab)
- Verify z-index is 999999
- Check if document.body is available (not in iframe)
- Verify CSS is not conflicting with Salesforce styles

Issue: Messages not sending
Solution:
- Check API endpoint exists and is working
- Use curl to test API: curl -X POST http://localhost:3000/api/chat -d '{"message":"test"}'
- Check network tab in DevTools for request/response
- Verify JSON parsing works

Issue: Salesforce CSP blocking widget
Solution:
- Add domain to CSP Trusted Sites
- Verify "Allow Script Requests" is checked
- Clear Salesforce cache
- Check security logs in Salesforce

Issue: Widget appears off-screen
Solution:
- Check position: fixed CSS properties
- Test on different screen sizes
- Check for parent elements with overflow: hidden
- Adjust bottom/right values in chat-widget.js

Issue: Performance is slow
Solution:
- Check bundle size: npm run build
- Optimize images
- Enable compression in next.config.js
- Use Vercel Analytics to identify bottlenecks
- Consider code splitting for large components

13. SECURITY CONSIDERATIONS

13.1 SECURITY BEST PRACTICES
────────────────────────────

Input Validation:
- Validate message length (max 500 characters)
- Check for XSS attempts
- Sanitize user input

export function sanitizeInput(input: string): string {
    return input.replace(/[<>]/g, '');
}

API Security:
- Implement rate limiting (prevent spam)
- Use HTTPS only
- Validate request headers
- Implement CORS properly

Rate Limiting (example):
import rateLimit from 'express-rate-limit';

const limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minutes
    max: 100 // limit each IP to 100 requests per windowMs
});

app.post('/api/chat', limiter, handler);

Authentication:
- Use API keys for backend requests
- Implement JWT tokens if needed
- Validate Salesforce session

Error Handling:
- Don't expose sensitive errors to client
- Log errors on server side
- Return generic error messages to user
